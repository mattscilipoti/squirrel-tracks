# VS Code Dev Container Setup - Squirrel Tracks

**One-Click Development Environment** with all dependencies pre-configured.

---

## 🚀 Quick Start (60 seconds)

### Prerequisites

- **VS Code** (v1.86+)
- **Docker Desktop** (installed and running)
- **Remote - Containers extension** (auto-installed from .vscode/extensions.json)

### Setup Steps

1. **Open this project in VS Code**

   ```bash
   code /home/matt/develop/clients/GreatEnough/ett
   ```

2. **VS Code will detect the dev container**
   - Look for notification: "Folder contains a Dev Container configuration"
   - Click "Reopen in Container"
   - OR: Press `Ctrl+Shift+P` and run "Dev Containers: Reopen in Container"

3. **Wait for setup** (~2-3 minutes first time)
   - Dockerfile builds
   - Dependencies install (Ruby gems, Node.js)
   - SQLite databases created
   - Post-create script runs

4. **See the success message**

   ```
   ✅ Squirrel Tracks Dev Environment Ready!
   ```

5. **Start developing!**
   ```bash
   # Terminal is already in /workspaces/squirrel_tracks
   cd backend && bundle exec rails server
   # Opens on http://localhost:3000
   ```

## 🛠️ Common Tasks

### Via Command Palette (Ctrl+Shift+P)

| Command                                           | Action                    |
| ------------------------------------------------- | ------------------------- |
| `Terminal: Run Task` → `Rails: Start Server`      | Start Rails on port 3000  |
| `Terminal: Run Task` → `Rails: Database Create`   | Create SQLite databases   |
| `Terminal: Run Task` → `Rails: Run Tests (RSpec)` | Run all tests             |
| `Terminal: Run Task` → `Web: Start Dev Server`    | Start web on port 5000    |
| `Terminal: Run Task` → `iOS: Pod Install`         | Install iOS pods          |
| `Debug: Start Debugging` → `Rails server`         | Start Rails with debugger |

### Via Terminal (in VS Code)

```bash
# Backend (Rails API)
cd backend
bundle exec rails server              # Start server (http://localhost:3000)
bundle exec rails console             # Interactive console
bundle exec rails db:migrate          # Run migrations
bundle exec rails db:reset            # Drop & recreate databases
bundle exec rspec                      # Run tests

# Web Frontend
cd web-frontend
python3 -m http.server 5000           # Start server (http://localhost:5000)

# iOS App
cd ios-app
pod install                           # Install CocoaPods
open EmergenTaskTracker.xcworkspace   # Open in Xcode
```

## 🔍 Debugging

### Rails Server Debugging

1. Set a breakpoint (click line number in editor)
2. Press `F5` or `Ctrl+Shift+D`
3. Select "Rails server" configuration
4. Server starts with debugger attached
5. Trigger breakpoint via HTTP request
6. Step through code in VS Code

### RSpec Test Debugging

1. Set breakpoint in test file
2. Press `Ctrl+Shift+P` → "Debug: Start Debugging"
3. Select "RSpec - current file"
4. Debugger pauses at breakpoint

### Console Debugging

```bash
# Inside container terminal
cd backend
bundle exec rails console

# Then inspect:
>> Session.first
>> Task.count
>> IntervalLog.all
```

## 🚨 Troubleshooting

### Container won't start

**Problem**: "Docker daemon not running"  
**Solution**: Start Docker Desktop, wait 30 seconds, retry

**Problem**: "Permission denied while trying to connect to Docker daemon"  
**Solution**:

```bash
# On macOS with Docker Desktop
sudo dscacheutil -flushcache

# On Linux
sudo usermod -aG docker $USER
newgrp docker
```

### Dependencies not installing

**Problem**: `bundle install` hangs or fails  
**Solution**:

```bash
# Inside container terminal
cd backend
rm Gemfile.lock
bundle install --no-cache
```

**Problem**: "Gem not found"  
**Solution**: Gems are installed in `/workspaces/squirrel_tracks/bundle` (persistent volume), not in container image

### Rails server won't start

**Problem**: "Address already in use (port 3000)"  
**Solution**:

```bash
# Kill existing process
lsof -i :3000 | grep LISTEN | awk '{print $2}' | xargs kill -9
# Or use different port
bundle exec rails server -p 3001
```

**Problem**: "Database is locked"  
**Solution**:

```bash
cd backend
rm storage/development.sqlite3
bundle exec rails db:create
```

### Port forwarding not working

**Problem**: Can't access localhost:3000 or localhost:5000  
**Solution**:

1. Check devcontainer.json has correct `forwardPorts`
2. In VS Code, check Ports tab (bottom panel)
3. Click "Forward a Port" if needed
4. Ensure services are running in container terminal

## 💾 Data Persistence

### SQLite Databases

- **Stored in**: `backend/db/` (mounted as volume)
- **Persists**: Even when container exits
- **Reset**: `bundle exec rails db:reset` (in container)

### Gems & Dependencies

- **Stored in**: `/workspaces/squirrel_tracks/bundle` (mounted as volume)
- **Persists**: Across container rebuilds
- **Size**: ~2 GB after full install

### SSH Keys

- **Mounted at**: `/home/vscode/.ssh` (read-only from host)
- **Use for**: Git operations, GitHub credentials

## 🔧 Rebuilding Container

### When to Rebuild

- After editing Dockerfile
- After major dependency changes in Gemfile
- When container is corrupted

### How to Rebuild

**Option 1: VS Code Command**

1. Press `Ctrl+Shift+P`
2. Run "Dev Containers: Rebuild Container"

**Option 2: Terminal**

```bash
# Outside VS Code (on host)
docker compose down
docker system prune
# Then reopen in VS Code
```
