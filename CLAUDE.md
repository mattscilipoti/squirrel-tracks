# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What's active

The live app is **`web-frontend/`** (vanilla JS, no server). It is **local-first**: all
data lives in a Yjs document persisted to IndexedDB. There is no backend or cloud
service. `backend/` (Rails), `ios-app/` and the retired `supabase/` folder are not in
the request path. Much of README.md's roadmap and the other top-level `*.md` setup docs
predate this; `ARCHITECTURE.md` is the current source of truth.

## Commands

```bash
npm test                                   # node --test web-frontend/js/*.test.cjs
node --test web-frontend/js/app-grid.test.cjs                  # one file
node --test --test-name-pattern="rename" web-frontend/js/*.test.cjs  # one test by name
npm run lint                               # eslint web-frontend/js
npm run format / npm run format:check      # prettier on web-frontend
web-frontend/start-server.sh               # serve on :5000 (WEBrick via root Gemfile)
npm run vendor                             # rebuild web-frontend/vendor/yjs.js (esbuild)
```

## Architecture

- Scripts load as classic `<script>` tags in order from `index.html`: `version.js`,
  `remote-changes.js`, `time-calculations.js`, `store.js`, `sync.js`, `app-grid.js`. They share
  top-level globals; when adding a cross-file global, also declare it in
  `eslint.config.mjs`. The one module script in `index.html` imports the vendored
  `vendor/yjs.js`, opens the store, starts `PeerSync` (joining from `#pair=`), and dispatches
  `app-store-ready`; `app-grid.js` creates the tracker from that event.
- `store.js` (`DataStore`) is the only code that touches Yjs. Its collections are **flat**
  `Y.Map`s keyed by `date|taskId|slot` etc. Never nest shared types: concurrent creation
  of the same nested map loses one side's data. Task records are JSON strings. See
  `ARCHITECTURE.md` for the layout and merge rules.
- `app-grid.js` (`GridTaskTracker`) owns the UI and an in-memory copy of the selected
  day (96-slot bubble grid, 24h x 15 min), task catalog, date navigation, reminder bell,
  and backup/import. Every edit writes through to the store at once
  (`store.setCell`, `saveDayFields`, ...); remote changes arrive via
  `store.onRemoteChange` -> `refreshFromRemoteChange`, which uses `RemoteChanges.diff`.
- Per-device state (selected date, reminder settings, the pairing secret) stays in localStorage;
  the shared data does not. Never put the pairing secret in the shared document.
- `sync.js` (`PeerSync`) pairs devices over y-webrtc. `sync.test.cjs` runs two devices in
  worker threads (y-webrtc allows one doc per room per realm); don't call `provider.destroy()`
  without `awareness.destroy()` (see `PeerSync.stop`).
- Tasks are reusable across days and identified by UUID; names are unique
  case-insensitively after trimming (`dedupeTasks` resolves collisions after a merge).
- `vendor/yjs.js` is generated by `npm run vendor` from `vendor-src/entry.js`; commit it
  after changing the yjs/y-indexeddb/y-webrtc/qrcode-generator versions.
- Tests are Node `.test.cjs` files. `store.test.cjs` uses the real `yjs` package;
  `app-grid.test.cjs` runs the browser scripts in a `vm` context with hand-built DOM
  fakes (see `fixture()`). Objects built inside the vm have another realm's prototypes,
  so that file's `deepEqual` compares JSON.

## Data and compatibility

The old Supabase migrations in `supabase/migrations/` are history only; do not add new
ones. Changes to the data layout must stay mergeable with existing copies on users'
devices (add keys; do not rename or restructure existing ones without a migration step
in `DataStore`).

## User-facing docs

README.md documents toolbar actions and reminder behavior in detail; update it when
changing user-visible behavior of the grid, Advanced actions (including Back up and
Import), or reminder.

## Working style

- Prefer the minimal change that solves the problem; don't refactor adjacent code unasked.
- Read only the files needed; avoid broad exploratory searches when the location is known.
- Don't spawn subagents unless asked.
- Skip re-verification reads after edits; run tests only when behavior changed.
- Keep replies short: result first, no recaps of what's visible in the diff.

## Style

Prettier: double quotes, semicolons, trailing commas, width 90. ESLint targets
ES2022 scripts (not modules) for browser files.
